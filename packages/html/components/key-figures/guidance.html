The few numbers that matter most on a page, each with what it measures, large enough to take in at a glance.

When to use

  • At the top of a page of statistics or open data: “755 mm average rainfall”.
  • On a dashboard or an account: “3 applications in progress”, “GH₵ 1,250 paid this year”.
  • In a staff tool, to show the size of a queue and what is overdue.

When not to use

  • For more than 4 numbers: put them in a table.
  • For a number people need to compare across many rows, such as each region: use a table, with a meter if a picture helps.
  • For a reference number at the end of a service: use the confirmation panel.

How to use

  • Use 2 to 4 figures. Put the most important first.
  • Keep the value short, with its unit: “755 mm”, “GH₵ 1,250”, “3.2 days”. Write the label in lower case after it, so they read as one phrase: “755 mm average rainfall”.
  • Say what a change is compared with, in words: “7% above normal”, “5 more than last year”. Do not show only an arrow or a colour.
  • Use ggds-key-figure--danger for a figure that needs action, such as “5 overdue”. The label must say why.
  • On a page heading or another dark background, add ggds-key-figures--inverse.
  • Say when the figures were last updated, near them.

Do

  • Give the unit with every value.
  • Say what a change is compared with.

Don't

  • Round so far that the number misleads.
  • Use colour alone to say a figure is good or bad.

Accessibility

What GGDS does

  • The figures are a list, so screen readers say how many there are before reading them (WCAG 1.3.1).
  • Values wrap rather than make a 320px screen scroll sideways (WCAG 1.4.10).
  • The danger edge is extra: the words carry the meaning (WCAG 1.4.1). In Windows contrast themes every edge keeps showing.

What you need to do

  • Write each value and label so they make sense read together, without the layout.
  • If the figures change while the page is open, do not announce every change: update them quietly.
