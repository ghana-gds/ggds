Questions and answers, or labels and values, as a list, with links to change them.

When to use

  • On a "Check your answers" page, at the end of a form, so people can check everything before they send it.
  • To show a record people can read and update, such as their application, licence or account details.

When not to use

  • To compare several items that share the same columns: use a table.
  • For a long list of links: use a plain list or cards.

How to use

  • Use the same wording for each key as the question it answers, shortened if it is long: "Date of birth", not "What is your date of birth?".
  • Show answers the way people gave them, written out in full: "27 March 1990", not "27/03/1990"; "Phone call", not "call".
  • Write "Not given" for an optional question left blank, so people can see it was not missed by mistake.
  • Give every row its own Change link, and say what it changes with hidden text: Change<span class="ggds-visually-hidden"> date of birth</span>. Rows people cannot change have no link.
  • A Change link goes back to that question with the answer filled in, then returns to the check page.
  • Break long check pages into sections with an <h2> above each list, such as "Your details" and "Your complaint".
  • Use ggds-summary-list--plain, without lines, for a short list inside a card or under a confirmation panel.

Do

  • Show every answer, including the ones people left blank.
  • Put a Send or Accept button after the last list, with what will happen: "Send complaint".

Don't

  • Use a table for questions and answers: a screen reader reads a table cell by cell, a description list question by answer.
  • Write "Change" with no hidden text: ten links all called "Change" make no sense in a list of links.

Accessibility

What GGDS does

  • It is a description list (<dl>), so screen readers announce each answer with its question (WCAG 1.3.1).
  • On phones each row stacks: question, answer, then the link, so nothing is squeezed. From 48rem they sit side by side.
  • Long answers, such as an email address or reference, wrap instead of making the page scroll sideways.
  • Change links are at least 44px tall.

What you need to do

  • Add hidden text to every Change link that says what it changes (WCAG 2.4.4).
  • Wrap each row in a <div class="ggds-summary-list__row">, with one <dt> and one or two <dd>.
  • Give the page a heading that says what the list is, such as "Check your answers before sending your complaint".
