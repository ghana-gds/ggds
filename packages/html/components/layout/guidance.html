Classes that arrange content on a page: stacks, rows that wrap, grids and a side column, with the GGDS spacing, text sizes and colours.

When to use

  • To arrange your own content between GGDS components: a list of services beside filters, a row of buttons, the parts of a card you made yourself.
  • Instead of writing your own spacing and grid CSS, or adding a CSS framework, so pages keep the same rhythm on every government website.

When not to use

  • To change how a GGDS component looks. Components already have their spacing; if one does not fit your page, tell us.
  • For a set of links to similar pages. Use cards in a ggds-card-grid.
  • To show different information on phones and computers. Hide only what is shown another way on that screen.

How to use

  • Stack (ggds-stack): put it on the element around things that go one above the other. It removes their own margins and puts the same space between each, so you do not set a margin on every paragraph.
  • Cluster (ggds-cluster): for buttons, tags and links side by side. They wrap onto the next line on a phone. Add ggds-cluster--spread for a title on one side and an action on the other.
  • Grid: ggds-grid fits as many columns of at least 16rem as the screen allows, with no breakpoints to choose. When you need a set number, use ggds-grid--2, --3 or --4: always one column on phones.
  • Scroll row: ggds-scroll-row on a grid of cards turns it, on phones, into a row people swipe through sideways, so a long set does not make the page long. Each card snaps into place and the next one peeks in. Use it for sets people browse, such as examples, stories or related links, never for steps or anything people must read in order. If the cards hold no links, give the row tabindex="0" and an aria-label, so keyboard users can scroll it.
  • Side column: ggds-with-aside puts the main content and a 20rem column side by side from desktops, and one under the other before. Add ggds-sticky to the side column to keep it in view while the page scrolls.
  • Gaps: change the space in a stack, cluster or grid with ggds-gap-1 to ggds-gap-12, steps of the spacing scale. Use small steps inside a box, 4 and 6 between related things, and 8 and above between sections.
  • Text, surfaces and sizes: the text classes use the type scale and the two GGDS weights; the surface and border classes use the GGDS colours, so they keep their contrast in every theme.
  • The layout classes sit in their own cascade layer, ggds.utilities, after the components. A layout class on a component wins over the component's own spacing, and your own CSS still wins over GGDS without !important. If you name the layers yourself, keep the order ggds.base, ggds.components, ggds.utilities.
  • If you load GGDS one file at a time, add components/layout.css.

Accessibility

What GGDS does

  • Every layout is one column on a 320px phone and gains columns only as the screen allows, so the page never scrolls sideways, also with a wide font. Only a scroll row moves sideways, inside itself.
  • The layout classes change only where things appear on the screen, never the order a screen reader or the keyboard follows.
  • ggds-text-muted and the surfaces keep text at 4.5 to 1 contrast or more.

What you need to do

  • Write the HTML in the order people should read it. A side column comes after the main content in the HTML.
  • Do not hide information on a screen size with ggds-from-tablet, ggds-from-desktop or ggds-below-desktop unless it is shown another way on that screen.
  • Use ggds-target or ggds-target-square on anything people tap that is not a GGDS button, link list or field, so it is at least 44px.
  • Do not make body text smaller than ggds-text-base; keep ggds-text-sm and ggds-text-xs for short labels and notes.
