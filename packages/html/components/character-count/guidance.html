Tells people how many characters they can enter in a textarea, and how many they have left as they type.

When to use

  • When there is a real limit on the length of an answer, such as a system that stores no more than 500 characters.

When not to use

  • To make people write less when there is no real limit. Ask a clearer question instead.
  • On a one-line text input.

How to use

  • Put ggds-character-count on the field and the limit in data-ggds-max. Add the limit as a hint after the textarea, and name it in the textarea's aria-describedby.
  • Do not put maxlength on the textarea: it silently cuts off what people paste. Let them write more, show that it is too long, and check the length on the server.
  • With the GGDS script, the hint becomes a count that updates as people type ("You have 120 characters remaining", "You have 12 characters too many").
  • In Django, a CharField with max_length and a Textarea gets a character count from the GGDS form renderer.
  • The count's text can be translated: data-ggds-remaining-one, data-ggds-remaining-other, data-ggds-over-one and data-ggds-over-other on the field, with {count} for the number. The Django and React parts set them from GGDS's text in the page's language.

Accessibility

What GGDS does

  • The count is shown at once, but screen readers hear it only when people pause typing, so it does not interrupt every key.
  • Too many characters is shown in words, in red and bold, never by colour alone.
  • Without JavaScript, people still see the limit as a hint.

What you need to do

  • Check the length on the server and show an error that says the limit, as in the second example.
