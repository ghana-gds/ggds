A trail of links showing where the page sits in the website.

When to use

  • On every page below the homepage, when your website has more than two levels.
  • When people often arrive on a deep page from a search engine and need a way up.

When not to use

  • On the homepage.
  • To show steps in a form. Breadcrumbs take people out of the form.
  • As the only way to move around. People still need the header.

How to use

  • Put the breadcrumbs at the top of the page, above the main heading.
  • Start with "Home", then one link for each level above this page.
  • Show where the page sits in the website, not the pages the visitor came through.
  • Use the same names as the pages' headings, shortened if they are long.
  • The last item is the current page. Do not link it, and mark it with aria-current="page".
  • On a narrow phone the trail wraps onto more lines; nothing is cut off. Short names keep it to one or two lines.

Do

  • Keep the trail the same on every page in a section.
  • Use short names: "Services", not "Our services to the public".

Don't

  • Link the current page to itself.
  • Type ">" or "/" between items; GGDS draws the arrows.

Accessibility

What GGDS does

  • It is a navigation area with an ordered list, so screen readers say how many steps there are.
  • The arrows between steps are drawn in CSS, so screen readers do not read them out.
  • Each link is at least 24px tall (WCAG 2.5.8), and the trail wraps instead of making the page scroll sideways.

What you need to do

  • Name it: <nav aria-label="Breadcrumb">.
  • Make the last step the current page: not a link, with aria-current="page".
  • Use one breadcrumb trail per page.
