Tables for data people need to compare, such as fees or opening hours.

When to use

  • For data with rows and columns that people compare: fees, opening hours, deadlines.

When not to use

  • For page layout.
  • For a single list of things. Use a list.
  • For data with many columns that people mostly read on phones. Split it into smaller tables, or offer it as a download.

How to use

  • Give every table a caption (ggds-table__caption) saying what it shows and when: "Licence fees, 2026".
  • Use <th scope="col"> for column titles, and <th scope="row"> for the first cell of a row when it names the row.
  • Right-align numbers with ggds-table__numeric, on the numbers and on their column title. Digits line up, so amounts are easy to compare.
  • Put units in the column title, "Fee (GH₵)", not in every cell. Use the same number of decimal places down a column.
  • Do not leave cells empty. Write "None" or "Not applicable".
  • Avoid merged cells. They are hard to follow with a screen reader.
  • Wrap the table in ggds-table-wrap with role="region", tabindex="0" and aria-labelledby pointing at the caption's id.

Do

  • Keep column titles short.
  • Put the most important column first.

Don't

  • Use a table to place things side by side.
  • Use an image of a table.

Accessibility

What GGDS does

  • Wide tables scroll inside their box, so the page does not scroll sideways at 320px (WCAG 1.4.10).
  • The box shows the gold focus ring when it has keyboard focus.
  • The header row has a thicker line under it, and numbers use figures of equal width.

What you need to do

  • Give every table a <caption>, and use <th> with scope for titles (WCAG 1.3.1).
  • Give the wrapper role="region", tabindex="0" and aria-labelledby, so keyboard users can scroll it and screen readers name it.
  • Use tables for data, never for layout.
