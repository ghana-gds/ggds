Links that look like tabs, for moving between views of the same section.

When to use

  • For views of one list, such as "News", "Public notices" and "Publications".
  • For a few pages about one thing, such as a service's "Overview", "Fees" and "How to apply".

When not to use

  • For content that should all be on one page. Use headings.
  • To show and hide parts of one page. GGDS has no in-page tabs; use headings, or a disclosure.
  • As the main navigation. Use the header.
  • For steps of a form.

How to use

  • Each tab is a normal link to its own page or address, such as ?kind=news, so it works without JavaScript and can be bookmarked.
  • Mark the current tab with aria-current="page".
  • Keep to two to five tabs, with names of one to three words.
  • Keep the tabs in the same order and place on every page they appear.
  • On a narrow phone the tabs stay on one line and the row scrolls sideways, so tabs at the end can be out of sight. Short names keep them all in view.
  • Change the page <title> to name the current tab, such as "Public notices – News".

Do

  • Name tabs after what people will find: "Public notices".

Don't

  • Add role="tab" or role="tablist".
  • Use more tabs than fit on a phone.

Accessibility

What GGDS does

  • They are ordinary links, so they work with every assistive technology and without JavaScript.
  • Every tab is at least 44px tall.
  • The current tab is shown by more than colour: it is bold, with a thick line under it.

What you need to do

  • Do not add ARIA tab roles. These are links and should be announced as links; people expect ARIA tabs to switch with arrow keys, without loading a page.
  • Mark the current tab with aria-current="page".
  • Name the navigation, such as aria-label="Kinds of news".
  • Give each tab's page its own title (WCAG 2.4.2).
