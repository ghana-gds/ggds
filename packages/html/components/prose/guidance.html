Styles for text from a content management system.

When to use

  • Around HTML written in a content management system (CMS), such as a Wagtail rich text field or a WordPress post body.

When not to use

  • Around GGDS components or forms. They have their own styles.
  • Around the whole page. Wrap only the CMS text.

How to use

  • Wrap the content in ggds-prose. It styles headings h2 to h4, paragraphs, lists, links, quotes and tables, and keeps lines to a comfortable reading length.
  • Clean the HTML before you show it. GGDS only styles it; your website must remove unsafe code first, with an allow-list of tags. Remove pasted style attributes and fonts too.
  • Start CMS headings at h2. The page title is the only h1.
  • Wrap tables in ggds-table-wrap when you clean the HTML. Without it, table cells break long words so the table squeezes onto a narrow screen, but wide tables still need the wrapper.
  • For a link to a document, say what it is and how big: "Licence guide (PDF, 2 MB)". Many people pay for data by the megabyte.

Do

  • Write link text that says where it goes: "Apply for a licence".
  • Use real lists, not lines starting with dashes.

Don't

  • Write "click here" or "read more".
  • Pick a heading level for its size.

Accessibility

What GGDS does

  • Links are underlined, so they are not shown by colour alone (WCAG 1.4.1).
  • Headings, lists and quotes are styled so their structure is visible.
  • Images shrink to fit the screen.

What you need to do

  • Keep headings in order (h2, then h3) without skipping levels, so screen reader users can move through the page (WCAG 1.3.1).
  • Make every link make sense on its own (WCAG 2.4.4).
  • Give every image alt text, or alt="" when it is decoration.
  • Clean the HTML before you show it: GGDS only styles it.
