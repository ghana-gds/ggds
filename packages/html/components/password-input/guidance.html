A password field with a Show button, so people can check what they typed before they send it.

When to use

  • When people sign in, or create or change a password.

When not to use

  • For a one-time code sent by SMS or email. Use a code input: it is not secret once used.
  • For a PIN: never ask for a mobile money or bank PIN on a website. People enter it on their phone.

How to use

  • Use the label "Password". When people create one, say what it needs in the hint, and only rules your system really has.
  • Set autocomplete="current-password" to sign in, and autocomplete="new-password" to create one, so password managers can fill and suggest it.
  • Let people paste. Do not limit the length to less than 64 characters.
  • Add data-ggds-module="password-input". The GGDS script shows the Show button, switches it to Hide, and hides the password again when the form is sent, so the browser does not keep it as plain text.
  • The button's words can be translated: data-ggds-show, data-ggds-hide, data-ggds-show-label, data-ggds-hide-label, data-ggds-shown and data-ggds-hidden on the field. The React, Astro and Django parts set them from GGDS's text in the page's language.

Accessibility

What GGDS does

  • The button says what it does ("Show password") and screen readers hear "Your password is visible" when it changes.
  • The password goes back to hidden when the form is sent.
  • Without JavaScript there is no button, and the field still works.

What you need to do

  • Never stop people pasting into the field (WCAG 3.3.8, accessible authentication).
  • If sign-in fails, say "The phone number or password is not right", without saying which.
