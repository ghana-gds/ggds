Links to move between pages of a long list.

When to use

  • For search results, news, notices, publications and other long lists.
  • Instead of "Load more" or endless scrolling. Each page is a normal link, so it works without JavaScript, can be bookmarked, and loads only one page of items at a time on slow or costly data.

When not to use

  • To move between steps of a form. Use a "Continue" button.
  • When everything fits on one page. Leave pagination out.
  • To split one article over several pages.

How to use

  • Put it after the list.
  • Show Previous and Next, and numbered pages in between: the first, the last, and a few either side of the current page, with "…" (ggds-pagination__ellipsis) where pages are left out.
  • Leave out Previous on the first page and Next on the last.
  • Above the list, say how many results there are and which ones are showing, such as "Showing 21 to 40 of 236 results".
  • Keep the search and filters in every link: ?q=licence&page=6, not just ?page=6. The Django tag does this for you.
  • Mark the current page with aria-current="page".

Do

  • Use real links with the page in the address.
  • Keep the same number of items on each page.

Don't

  • Lose the visitor's search when they change page.
  • Use buttons and a script to load the next page.

Accessibility

What GGDS does

  • Every link is at least 44px square, and the row wraps on narrow screens.
  • The current page is shown by more than colour: it is filled in, and screen readers announce it as the current page.
  • In the examples and the Django tag, the "…" is hidden from screen readers and Previous and Next carry the hidden word "page".

What you need to do

  • Name the navigation by what is being paged, such as aria-label="Pages of results".
  • Mark the current page with aria-current="page".
  • Give number links a full name, such as aria-label="Page 3".
  • Give Previous and Next hidden text when they are not clear alone, such as "Next page of results".
