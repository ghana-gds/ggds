A box over the page that asks people to confirm something before it happens, such as deleting a draft.

When to use

  • To confirm an action that cannot be undone, such as deleting a draft application or withdrawing one.
  • For the timeout warning.

When not to use

  • For anything people need to read carefully, fill in or come back to: use a page.
  • For messages: use a notice on the page. A dialog interrupts people, and some find it hard to use with a screen magnifier.

How to use

  • Make the opener a link to a confirmation page, so it works without JavaScript, and add data-ggds-dialog="<the dialog's id>". With the GGDS script, the link opens the dialog instead.
  • Use the browser's <dialog> with class="ggds-dialog" and aria-labelledby naming its heading.
  • Ask a question as the heading ("Delete this draft?") and say what will happen. Name the action on the button ("Delete draft", not "OK"), and give a way out ("Cancel") with data-ggds-dialog-close.
  • Put the action in a form that posts, inside the dialog, so the server does it, as on the confirmation page.
  • Use ggds-dialog--warning for an action that cannot be undone.

Accessibility

What GGDS does

  • The browser keeps focus inside the dialog, makes the page behind it unavailable, closes it with Escape and returns focus to the link that opened it.
  • Focus starts on the first button, which is never the action that cannot be undone.
  • Without JavaScript, the link opens the confirmation page.

What you need to do

  • Keep it short: a heading, a sentence and two buttons.
  • Put the safe choice first, so it gets focus.
