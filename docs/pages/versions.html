The current version is ${version}. Every change is listed in What’s new.

Where to get each version

  • Download: ggds-<version>.zip from the releases page, with a checksum (SHA256SUMS) and an integrity value for every file (integrity.json). This is the recommended way for government websites.
  • npm: @ggds/tokens, @ggds/themes, @ggds/css, @ggds/js and @ggds/astro, published with provenance, so anyone can check they were built from this repository.
  • PyPI: ggds-django, for Django and Wagtail.

All packages share one version number and are released together, so @ggds/css ${version} always goes with @ggds/js ${version}.

What a version number means

GGDS uses semantic versioning: major.minor.patch.

  • Patch (0.1.0 to 0.1.1): fixes and documentation. Update without checking your pages.
  • Minor (1.1 to 1.2): new components, classes, options or tokens. Nothing you use stops working. Update when you are ready.
  • Major (1.x to 2.0): changes that may need you to change your HTML or CSS, such as a renamed class or removed token. Each one comes with a guide to updating.

Before version 1.0, GGDS is a draft: a minor version (0.1 to 0.2) may also contain changes that need you to change your pages. They are listed first in What’s new, under "Changes you need to make".

What counts as a breaking change

These are breaking changes, and only happen in a major version (or a minor version before 1.0):

  • removing or renaming a class, token, file, package export, Astro prop or Django template tag;
  • changing the HTML a component needs;
  • removing support for a browser.

These are not breaking changes: how a component looks (spacing, colour within its contrast rules), new classes and tokens, accessibility fixes, and changes to the guidance. An accessibility fix may change a component's HTML in a minor version if leaving it would keep a barrier in place; it is marked clearly in What’s new.

How things are removed

  1. The thing is marked deprecated in What’s new and in its documentation, with what to use instead. It keeps working.
  2. It is removed in the next major version, at least 6 months later.

For example, the --site-* token names in @ggds/tokens/compat-site.css are deprecated, for sites moving from the MoCDTI platform, and will be removed in GGDS 2.0.

Component status

Each component page shows a status:

  • Stable: used on live government websites and not expected to change. It changes only as described above.
  • Beta: works, is tested and is used on the MoCDTI platform. It may still change before version 1.0, after research or the accessibility audit. Any change is listed in What’s new.
  • Alpha: new. It is tested automatically, but not yet used on a live government website, and may change in any release after research. Use it, and tell us how it works for you.

See every component and its status on the components page.

How long a version is supported

  • The latest version gets every fix.
  • After version 1.0, the previous major version gets security and accessibility fixes for 12 months after the next one is released.
  • Before version 1.0, only the latest version is supported. Keep to the latest 0.x release.

Browsers

GGDS supports current versions of Chrome, Edge, Firefox and Safari, on phones and computers, and Samsung Internet and Opera on Android. The styles use cascade layers, which these browsers have had since 2022. Some details, such as card hover effects and the wide-screen header, use newer CSS; browsers without it show a plainer version that still works. Every page works without JavaScript.

Security problems

Do not report a security problem in a public issue. Follow the security policy: report it privately on GitHub, and we will reply within 5 working days.
